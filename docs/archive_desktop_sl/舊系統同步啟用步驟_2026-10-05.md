# LINE 與舊系統同步啟用步驟

更新日期：2026-10-05

## 目前狀態

LINE 官網、Vercel 與 Supabase 的橋接框架已部署完成，但正式同步開關維持關閉。這台電腦不是每天操作舊系統的營業主機，因此目前不會讀取或寫入實際舊系統。

## 正式資料流

1. 客戶從 LINE 官網下單，訂單先安全寫入 Supabase。
2. 同一筆交易建立待同步工作，避免訂單已成立但同步工作遺失。
3. 營業主機上的同步程式以加密連線向 Vercel 取回工作。
4. 同步程式把訂單寫入營業主機 SQL Server，再回報舊系統訂單編號。
5. 舊系統人工建立或修改的訂單，由同步程式比對指紋後匯入 Supabase。
6. 每筆工作都有唯一鍵、簽章、五分鐘時效、Nonce、防重複、租約、重試及衝突紀錄。

## 到營業主機後的啟用順序

### 1. 只做檢查

- 確認舊系統真正使用的 SQL Server 名稱、執行個體與資料庫。
- 建立專用 SQL 帳號；只授權讀取客戶及訂單，並只授權新增訂單與核准過的狀態欄位。
- 不使用系統管理員帳號，不開放 SQL Server 到網際網路。
- 執行 `npm run legacy:inspect`，確認 `customers`、`gas_oders`、商品數量欄位、取消欄位及日期格式。

### 2. 只比對、不寫入

- 設定 Vercel 與營業主機共同使用的 32 位元組以上隨機密鑰；密鑰不得放進報告或程式碼。
- 營業主機執行 `npm run legacy:dry-run`。
- 核對新增、修改、取消、客戶找不到、地址衝突及商品對照。
- `LEGACY_STATUS_MODE` 保持 `review`，未核對舊系統狀態欄位前不會靜默標記成功。

### 3. 小量正式測試

- 先選一名安全測試客戶及一筆測試訂單。
- Vercel 設定 `LEGACY_SYNC_ENABLED=true`，營業主機設定 `LEGACY_SYNC_APPLY=true`。
- 執行一次 `npm run legacy:sync-once`，同時核對 LINE、Supabase 與舊系統三邊訂單編號、金額、商品、地址及狀態。
- 確認取消欄位實際值後才設定 `LEGACY_CANCEL_WRITE_VALUE`。

### 4. 自動執行

- 使用 Windows 工作排程器，每分鐘執行一次 `npm run legacy:sync-once`。
- 工作必須使用最低權限帳號，失敗時保留報告並告警，不自動覆蓋衝突資料。
- 連續成功一段觀察期後，才把 `LEGACY_STATUS_MODE` 改成 `acknowledge`，或依實際欄位加入狀態寫入規則。

## 地址與會員規則

- 舊系統客戶編號是跨系統對照鍵，電話只用於查找候選，不直接決定綁定。
- 多個地址保留為多筆地址資料；本人搬家、新增地址及新住戶接手是三種不同操作。
- 歷史訂單保留當時配送地址，不因後續搬家而改寫。
- LINE 會員、登入狀態、綁定審核及通知紀錄只保存在 Supabase，不回寫舊系統。

## 發生異常時

1. 先把營業主機的 `LEGACY_SYNC_APPLY` 改回 `false`。
2. 保留同步游標、工作佇列、兩邊訂單編號與衝突報告。
3. 不刪除訂單、不重設游標、不大量重跑。
4. 修正欄位或對照後，讓失敗工作依原唯一鍵重試。

## 啟用前仍須取得

- 真正營業主機的 SQL Server 連線位置與資料庫名稱。
- 現行 `gas_oders` 欄位、取消值與狀態規則。
- 一名安全測試客戶。
- 接收同步失敗告警的管理 LINE 帳號。
